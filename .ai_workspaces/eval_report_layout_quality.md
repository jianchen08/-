# 评估报告：科技树节点布局质量评估

## 评估标准
> 节点不再堆叠，同一领域聚集但互不重叠，不同领域有间距，整体布局清晰可读

## 评估对象
- **主要文件**: `src/components/TechTree.tsx`（布局核心逻辑）
- **数据文件**: `public/*.json`（12个领域、7个时代、约200+节点）
- **类型定义**: `src/types/index.ts`

---

## 逐条验收评估

### AC-01: 节点不再堆叠 — ❌ FAIL

**验证方法**: 代码静态分析 — timeline 布局算法的碰撞检测能力

**证据**:

1. **Y轴布局**（`TechTree.tsx:198`）:
   ```typescript
   const yBase = domainIdx * 120;
   ```
   同一领域的所有节点共享同一个 Y 基线（`yBase`），仅靠抖动（jitter）区分。

2. **抖动机制**（`TechTree.tsx:199-205`）:
   ```typescript
   let hash = 0;
   for (let i = 0; i < node.id.length; i++) {
     hash = ((hash << 5) - hash) + node.id.charCodeAt(i);
     hash |= 0;
   }
   const jitter = (Math.abs(hash) % 60) - 30;
   positions[node.id] = { x: xPos + jitter * 0.3, y: yBase + jitter };
   ```
   - Y轴抖动范围: ±30px
   - X轴抖动范围: ±9px（jitter * 0.3）
   - **抖动是确定性的哈希值，不包含碰撞检测逻辑**

3. **节点尺寸**（`TechTree.tsx:24-26`）:
   ```typescript
   function hubToSize(hubScore: number): number {
     return 20 + (hubScore / 100) * 30;
   }
   ```
   节点直径范围: 20px ~ 50px

4. **密度分析**（以信息技术领域为例）:
   - IT领域数据: ~1675行JSON，约 80+ 个节点
   - 信息时代占X轴35%权重 → 1750px 宽度
   - 平均X间距: 1750 / 80 ≈ **22px**
   - 最大节点直径: **50px**
   - **结论: 节点宽度远大于平均间距，必然产生大量重叠**

5. **同领域同年份节点**: 年份相同或相近的节点（如2015-2017年间的多个AI技术）会获得几乎相同的 X 坐标，仅靠 ±30px 的 Y 抖动区分，而节点最大半径为 25px，**多个 50px 直径的节点在 ±30px 范围内根本无法避免重叠**。

**结论**: 时间轴布局中，高密度领域（特别是IT、物理在信息时代）**必然存在节点堆叠**，因为缺乏碰撞检测和避让机制。

### AC-02: 同一领域聚集但互不重叠 — ⚠️ PARTIAL (聚集✓, 不重叠✗)

**验证方法**: 代码分析 — 领域聚集机制 + 碰撞分析

**证据**:

1. **聚集机制**（`TechTree.tsx:197-198`）:
   ```typescript
   const domainIdx = domainMap.get(node.domain) ?? 0;
   const yBase = domainIdx * 120;
   ```
   同一领域的节点被分配到同一 Y 行（`domainIdx * 120`），**聚集效果良好** ✓

2. **互不重叠问题**: 见 AC-01 分析，同一行内节点间距不足导致重叠。

3. **Y行间距分析**:
   - 相邻领域 Y 间距: 120px
   - 节点最大半径: 25px
   - 抖动范围: ±30px
   - 有效最小间距: 120 - 25 - 30 - 25 - 30 = **10px**（勉强不重叠）
   - 但这仅适用于**不同领域之间**，同一领域内无此保障

**结论**: 领域聚集效果良好，但同一领域内的节点**无法保证不重叠**。

### AC-03: 不同领域有间距 — ✅ PASS

**验证方法**: 代码分析 — 领域行间距计算

**证据**:

1. **领域行间距**: `domainIdx * 120` → 每个领域占120px的Y轴空间
2. **12个领域的总Y轴跨度**: 11 × 120 = 1320px
3. **最坏情况间距**: 
   - 领域A最底部节点: y = yBase_A + 30（最大抖动）
   - 领域B最顶部节点: y = yBase_B - 30（最小抖动）
   - 间距 = 120 - 30 - 30 = **60px**（大于最大节点直径50px）

**结论**: 不同领域之间有足够的间距（≥60px），不会跨领域重叠 ✓

### AC-04: 整体布局清晰可读 — ⚠️ PARTIAL

**验证方法**: 代码分析 — 宏观结构 + 微观可读性

**正面证据**:
1. **宏观结构清晰**: 时间轴（X轴按年代排列）+ 领域带（Y轴按领域分行），形成清晰的网格结构
2. **时代加权分配**: `eraWeights = [0.08, 0.10, 0.10, 0.10, 0.12, 0.15, 0.35]` 合理分配空间
3. **视觉辅助**: 图例、颜色编码、节点大小编码（枢纽值）增强可读性
4. **交互支持**: 缩放、平移、框选、节点详情面板
5. **默认布局**: 应用默认使用 `timeline` 布局（`App.tsx:31`），确保用户首次看到的就是最优布局

**负面证据**:
1. **高密度区域重叠**: 信息时代IT领域的节点堆叠严重影响可读性
2. **字体过小**: `'font-size': '8px'`（`TechTree.tsx:238`），在节点密集区域更难辨识
3. **X轴总宽度仅5000px**: 对于200+节点来说偏窄，导致密集区域节点挤在一起
4. **缺乏智能避让**: 确定性哈希抖动无法保证所有节点可见

**结论**: 宏观布局结构设计合理，但微观层面的节点堆叠问题影响最终可读性。

## 具体问题清单

### 问题 1: 同领域同时间段节点堆叠
- **文件**: `src/components/TechTree.tsx:199-205`
- **描述**: 时间轴布局中，同一领域的节点仅使用确定性哈希抖动（±30px Y, ±9px X）分散，不包含碰撞检测。在高密度场景下（如IT领域信息时代约80+节点），节点直径（20-50px）远大于平均间距，必然导致重叠。
- **严重程度**: 高

### 问题 2: Y轴领域行间距与节点尺寸/抖动不匹配
- **文件**: `src/components/TechTree.tsx:198`
- **描述**: `domainIdx * 120` 的行间距在考虑最大节点尺寸(50px)和抖动(±30px)后，相邻领域的有效最小间距仅剩约10px，裕度不足。
- **严重程度**: 中

### 问题 3: X轴总宽度不足
- **文件**: `src/components/TechTree.tsx:187`
- **描述**: `segmentWidth = weight * 5000`，信息时代仅占1750px，无法容纳80+个IT节点。
- **严重程度**: 中

### 问题 4: 节点标签字体过小
- **文件**: `src/components/TechTree.tsx:238`
- **描述**: `'font-size': '8px'` 在高密度重叠区域几乎无法辨识。
- **严重程度**: 低

## 修复建议

### 建议 1: 实现碰撞检测与迭代避让算法
在时间轴布局的 `positions` 计算完成后，添加碰撞检测循环：
1. 计算所有节点对的距离
2. 对距离小于两节点半径之和的节点对施加排斥力
3. 迭代直到无碰撞或达到最大迭代次数
4. 估算工作量: 约50行代码

### 建议 2: 增加领域行间距
将 `domainIdx * 120` 修改为 `domainIdx * 180` 或动态计算间距，确保考虑最大节点尺寸和抖动后仍有 ≥40px 裕度。

### 建议 3: 增大X轴总宽度或使用自适应宽度
将 `weight * 5000` 中的 5000 增大到 10000-15000，或根据每行节点数量动态计算宽度，确保平均间距 ≥ 最大节点直径。

### 建议 4: 实现节点标签自适应隐藏
在缩放级别较低时隐藏标签，仅在用户放大到一定程度或hover时显示标签，避免视觉混乱。

**评估状态**: ❌ 未通过
