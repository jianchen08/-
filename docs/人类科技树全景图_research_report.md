# 人类科技树全景图项目技术调研报告

---

## 基本信息 [必填]
- **调研类型**: technology（技术调研）
- **调研目标**: 为人类科技树全景图项目选择最佳技术栈，重点关注可视化库选型、前端框架、数据格式、PDF导出方案和部署方案
- **调研时间**: 2026-05-08

## 背景 [可选]
人类科技树全景图项目旨在展示人类科技发展的完整脉络，需要支持500-1000+节点的大规模交互式科技树可视化。项目核心需求包括：
- 展开/折叠功能
- 搜索/筛选功能
- 多种布局算法（dagre树形/force力导向/layered分层）
- PDF/SVG导出能力
- 纯静态部署优先

## 摘要 [必填]
本调研报告针对人类科技树全景图项目进行了全面的技术选型调研。**核心建议**：

1. **可视化库首选 Cytoscape.js**：综合性能最强，支持dagre布局算法，原生支持大规模图数据，适合展示科技树结构
2. **备选方案 React Flow + Dagre**：如采用React技术栈，React Flow配合dagre-layout是现代且灵活的选择
3. **前端框架推荐 React**：组件化生态完善，与主流可视化库集成便捷
4. **PDF导出方案推荐 html2canvas + jsPDF**：纯前端实现，部署简单，效果可接受
5. **部署方案推荐纯静态部署**：GitHub Pages零成本，Vercel体验更好

## 关键发现 [必填]

### 发现 1: Cytoscape.js 是大规模图可视化的最佳选择
- **内容**: Cytoscape.js 在处理500-1000+节点时性能表现优异，原生支持dagre布局算法，提供丰富的交互功能（展开/折叠/搜索/筛选），且完全开源免费
- **来源**: 多个技术社区评测和官方文档
- **信源等级**: 🟢A（官方文档 + GitHub仓库）
- **可信度**: 高

### 发现 2: D3.js 灵活性最高但学习曲线陡峭
- **内容**: D3.js 是最灵活的数据绑定可视化库，几乎可以实现任何可视化效果，但在大型项目中代码复杂度高，需要自行实现布局算法
- **来源**: 技术社区共识
- **信源等级**: 🔵B（Stack Overflow + 知名技术博客）
- **可信度**: 高

### 发现 3: React Flow 是React生态中处理流程图的最佳方案
- **内容**: React Flow专为React设计，提供了开箱即用的节点/边概念，支持自定义节点组件，与React生态无缝集成
- **来源**: GitHub仓库和官方文档
- **信源等级**: 🟢A（GitHub官方仓库）
- **可信度**: 高

### 发现 4: JSON 是Web应用数据交换的最佳格式
- **内容**: JSON相比YAML和CSV具有更好的解析性能、更广泛的工具支持、更简洁的语法，与JavaScript原生集成良好
- **来源**: JSON官方规范和技术社区
- **信源等级**: 🟢A（json.org官方文档）
- **可信度**: 高

### 发现 5: html2canvas + jsPDF 是纯前端PDF导出的主流方案
- **内容**: 该方案完全基于浏览器端实现，无需服务端支持，实现相对简单，但在大尺寸图表导出时可能出现质量问题
- **来源**: 技术社区广泛使用
- **信源等级**: 🔵B（npm社区 + 技术博客）
- **可信度**: 中高

### 发现 6: 纯静态部署完全可行
- **内容**: 对于纯前端项目，GitHub Pages和Vercel都提供零成本的静态部署方案，GitHub Pages适合开源项目，Vercel提供更好的CDN和自动HTTPS
- **来源**: 各平台官方文档
- **信源等级**: 🟢A（官方文档）
- **可信度**: 高

### 发现 7: 科技史时代划分标准体系
- **内容**: 主流科技史采用六时代划分：远古时代→古代→中世纪→文艺复兴→工业革命→现代（信息时代），或四时代划分：古代文明、中世纪、科技革命、现代科技
- **来源**: 学术文献和权威百科
- **信源等级**: 🔵B（学术论文 + 权威百科）
- **可信度**: 中

## 建议方案 [可选]

### 建议 1: 可视化库选型 - Cytoscape.js
- **内容**: 首选 Cytoscape.js 作为核心可视化引擎
- **理由**: 
  1. 原生支持dagre布局算法，适合树状结构
  2. 性能优秀，可处理1000+节点
  3. 丰富的交互API（展开/折叠/筛选）
  4. 完全开源免费，无商业授权风险
  5. 社区活跃，文档完善
- **优先级**: 高

### 建议 2: 备选方案 - React Flow + Dagre
- **内容**: 如项目采用React技术栈，React Flow + dagre-layout是更现代的选择
- **理由**:
  1. 与React生态无缝集成
  2. TypeScript支持好
  3. 组件化设计，易于维护
  4. 支持自定义节点组件，灵活性高
- **优先级**: 中

### 建议 3: 前端框架 - React
- **内容**: 推荐使用 React 作为前端框架
- **理由**:
  1. 组件化架构适合复杂UI
  2. 生态丰富，有大量可复用组件
  3. 与可视化库集成成熟
  4. TypeScript支持完善
- **优先级**: 高

### 建议 4: 数据格式 - JSON
- **内容**: 推荐使用 JSON 作为主要数据存储和交换格式
- **理由**:
  1. JavaScript原生支持，前端加载无障碍
  2. 解析性能优秀，适合大规模数据
  3. 嵌套结构良好，适合表达科技树的层级关系
  4. 工具生态丰富，便于数据编辑和管理
- **优先级**: 高

### 建议 5: PDF导出 - html2canvas + jsPDF
- **内容**: 使用 html2canvas + jsPDF 实现纯前端PDF导出
- **理由**:
  1. 无需服务端，降低部署复杂度
  2. 实现相对简单，社区资源丰富
  3. 可满足基本导出需求
- **优先级**: 高

### 建议 6: 部署方案 - Vercel
- **内容**: 推荐使用 Vercel 进行部署
- **理由**:
  1. 全球CDN加速，用户体验好
  2. 自动HTTPS
  3. 与GitHub无缝集成
  4. 免费额度充足（100GB/月带宽）
  5. 预览部署功能强大
- **优先级**: 高

### 建议 7: 科技史分类体系
- **内容**: 采用六时代划分 + 十大科技领域分类
- **理由**:
  1. 时代划分清晰，符合学术共识
  2. 领域覆盖全面
  3. 便于数据组织和用户理解
- **优先级**: 中
